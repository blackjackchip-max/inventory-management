01 · System Overview

Two independent processes, joined by HTTP

No shared build step, no shared runtime — the client and server are started, stopped, and deployed separately.

04 · Request Lifecycle

One filter change, end to end

Traced for the Filter Bar (Time Period, Warehouse, Category, Order Status) driving the dashboard summary — the same path every filter-aware view follows.

1
FILTER INPUT
User changes a <select> in FilterBar.vue, bound to the useFilters() singleton refs.
2
REACTIVE TRIGGER
The view's watch([...4 refs], loadData) fires; getCurrentFilters() maps the refs to { warehouse, category, status, month }.
3
CLIENT REQUEST
api.js builds a URLSearchParams, skipping any filter still set to 'all', and issues an axios GET to localhost:8001.
4
SERVER RECEIVE
FastAPI parses and type-checks the query params straight from the endpoint's function signature.
5
IN-MEMORY FILTER
apply_filters() and filter_by_month() run over the module-level lists from mock_data.py — case-insensitive category match, QUARTER_MAP for Q1–Q4 buckets.
6
SERIALIZE exception
Most endpoints validate the result through a Pydantic response_model. /api/dashboard/summary returns a plain dict instead — unvalidated on the way out.
7
CLIENT STORE
Axios resolves response.data into a raw ref — allOrders, inventoryItems, summary.
8
DERIVE & RENDER
View-level computed() properties turn the raw ref into chart series and formatted values; the template re-renders reactively.
Filter System — the same four filters (Time Period → month, Warehouse, Category, Order Status) are shared globally via the useFilters singleton and applied uniformly on the backend to every filter-aware endpoint. Inventory intentionally has no month filter — inventory has no time axis.

06 · Field Notes

Deviations found during investigation

Not defects in the demo's purpose — noted here because they'd matter to anyone extending this codebase.

ORPHANED
Backlog.vue is not routed

main.js registers 6 routes; Backlog.vue isn't one of them. Dashboard.vue implements its own inline backlog table instead.

API GAP
Frontend calls endpoints the backend doesn't implement

client/src/api.js defines calls to /api/tasks* and /api/purchase-orders*; no matching routes exist in server/main.py — these calls would 404.

VALIDATION
/api/dashboard/summary skips Pydantic

Unlike /api/inventory and /api/orders, this endpoint returns a raw dict with no response_model — no validation or serialization guarantee on the response shape.

NO WRITES
All data is process memory

Every list endpoint reads from module-level Python lists loaded once at startup. There's no persistence layer, so even if the missing write endpoints existed, a restart would discard their effects.
